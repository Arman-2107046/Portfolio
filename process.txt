--------------------------------------------------------------------------------
0. RULES OF ENGAGEMENT (APPLY TO EVERY STEP)
--------------------------------------------------------------------------------

R1. One step = one commit = one push. Never combine two steps into one commit.

R2. Before every commit, run the gate:
      npm run lint && npx tsc --noEmit && npm run build
    If any command fails, fix it. Do not commit broken code. Do not disable
    a lint rule to get past it unless you write the reason in the commit body.

R3. Commit format (Conventional Commits):
      <type>(<scope>): <imperative summary under 60 chars>

      Body (optional, wrap at 72): what changed and why.

    Types: feat, fix, style, refactor, perf, chore, docs, ci, build, test.

R4. Push command after every commit:
      git add -A
      git commit -m "..."
      git push origin main

R5. After each step, print a short status block to the console:
      STEP <n> COMPLETE
      Files touched: <list>
      Design decision: <one sentence, why you chose what you chose>
      Commit: <hash + message>
      Next: STEP <n+1>

R6. Write real copy. Never ship lorem ipsum, never ship "Project Title Here",
    never ship placeholder numbers. If a fact is missing, write a realistic
    line and add it to OPEN-QUESTIONS.md for Arman to confirm.

R7. Accessibility and responsiveness are not a final phase. Every component you
    build is keyboard operable, has visible focus, passes AA contrast, and works
    at 375px the moment it is committed.

R8. If you are unsure between two design options, build the more restrained one.

Direction: quiet, engineered, editorial. The site should feel like technical

after it stays disciplined.

Required quality floor:
